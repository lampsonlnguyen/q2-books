# CrossPod v0.10 development — exact 10–12pt fonts

## Decision

**CrossPod Q2 reading fonts are limited to 10, 11 and 12 points.**
There is no reading-font option above 12 pt. The default is 12 pt and
Center on Reading settings → Size cycles: 10 → 11 → 12 → 10.
The two primary font families remain NotoSansExtended and NotoSerifExtended.

CrossInk's `src/ReaderFontSizeStep.h` confirms that its *scalable TTF*
font path supports every whole-point size from 8 through 22; its original
bitmap built-ins only offer 10,12,14,16. CrossPod uses CrossPoint's bitmap
`.cpfont` engine, so it needs an actual raster, advance/kerning metrics,
italic/bold faces and fallback glyph pack **for each selected point size**.
Reusing a 12pt font with a 10pt label is incorrect and prohibited.

## Implementation on v0.10 branch

- `Typography.hpp`: three accepted sizes, max=12, min=10, default=12.
  Older 14/16/18pt saved settings migrate to 12pt, and old 8/9pt development settings migrate to 10pt.
- `crosspod_reader.cpp`: both Q2 wheel/touch execution paths cycle through
  the three permitted sizes; CrossPoint Section repagination is triggered.
  Each family+size has a distinct renderer font ID/cache signature.
- `fetch_q2_fonts.py`: retain only the SHA-256-verified 12pt release assets
  for two main families and 14 fallback scripts; omit large fonts >12pt.
- `build_q2_small_font_assets.py`: generate 10–11pt CPFont v4 fonts with the
  CrossPoint upstream font converter pinned to commit
  `42d58daaabcf469a2e5e1ba871714fb9dcf51d29`. Includes CJK,
  Hangul, ten Indic families, Arabic, Hebrew, and both primary fonts.
  Some of these families are absent from the pinned CrossPoint YAML snapshot;
  the Q2 CI host supplies missing Indic and CJK sources from Ubuntu 24.04
  `fonts-noto-core` and `fonts-noto-cjk`. These Linux-host packages are used
  only to generate CPFONT files; they are NOT installed on the Q2.
  Copies original font license notices and writes a generated SHA-256 list.
- The Q2 CI build checks every generated asset and renders a Vietnamese
  EPUB at all three sizes and both families under the actual MIPS32r2 ELF
  in QEMU. It requires 14/14 script fallbacks at each size and distinct
  font rasters. This is stronger than only checking that files exist.
- Host unit tests cover the exact size range, step cycling, filename
  resolution, saved settings, and backward compatibility.

## Source integrity

Prebuilt 12pt source assets have pinned SHA-256 digests. The font-generation
tooling is pinned to a CrossPoint commit, but some font-source URLs
and Ubuntu font packages are not individually SHA-256 pinned. Source package
versioning and output hashes still need to be recorded for reproducibility. Generated packs are checksummed for transport and
integrity during packaging but must not be advertised as *bitwise
reproducible* until original TTF/OTF source blobs are SHA-256 pinned.
A permanent font-pack release with source and output hashes is a follow-up.

## Release gates

- Host GCC and Clang builds/CTest pass.
- Full MIPS QEMU build produces all 48 cpfont files (16 families × 3 sizes).
- Main font and fallback render coverage passes at 10, 11 and 12pt.
- On a physical Shanling Q2: select each size, inspect Vietnamese, Arabic,
  Hebrew and CJK books, verify line spacing/kerning and italic/bold, confirm
  user position survives repagination/restart, and record page-turn latency,
  RSS and SD-card I/O. Smaller glyphs must not collide or get clipped.
- Do not merge/release before a complete Q2 font asset build and visual
  hardware validation. The existing v0.8 beta and v0.9 HTTPS PR are separate.
