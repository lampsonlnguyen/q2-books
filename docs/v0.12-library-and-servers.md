# M4: library and servers

Milestone M4 (planned as v0.12) finishes what Books does with catalogs and
with a large library on the card. It is on `main` after 1.1.1. Everything
here was tested on the host (GCC, Clang, ASan) and on the fake Q2 (the
card app with its real input socket and framebuffer). It has **not** been
measured on a physical Q2 yet (see M1 in the README).

## Several catalog servers

**Online** on the home screen now opens a list of catalog servers instead
of going straight to one catalog:

- Each saved server shows its name, its host and its user name. OK opens
  its catalog. Back from the catalog's first page returns to the list.
- **+ Add server** opens a form: Name, URL, User, Password, Save. OK on a
  field opens the T9 keyboard to type it. For the URL, the user name and the
  password, the two punctuation keys also have the characters addresses
  need: `,'-:;@_` and `./?!=&%~#`. The search keyboard keeps Q2's own
  layout. A password shows as `*`, except the letter you are still typing.
- **Edit a server** then a server opens the same form, with **Delete
  server** at the end. Delete asks for a second press.
- Up to 8 servers. Save refuses a URL that is not `http://` or `https://`,
  and a password with no user name.

The servers live in `.books/connected.conf`. The first one can still be the
old top-level `opds_url=`; every other one is a `[server]` block:

```ini
[server]
name=Calibre-Web
opds_url=https://books.example.com/opds
opds_username=YOUR_USER
opds_password=YOUR_PASSWORD
```

A server's user name and password are sent as HTTP Basic credentials, and
only to that server's own origin (scheme, host and port). Catalog links are
already limited to the same origin, so a feed can't send them anywhere else.
Kavita needs no user name: its key is part of the OPDS URL.

When you change servers on the Q2, Books rewrites `connected.conf`. It
writes a new file, flushes it to the card, then renames it over the old
one, with mode 0600. The sync settings are kept; comments are not.

Use `https://` for any server outside your home network. Over `http://`
the password crosses the network unencrypted.

## Offline catalog and retry

- Every catalog page Books reads is kept on the card in `.books/opds-cache/`:
  64 pages and 8 MB at most, oldest dropped first, mode 0600 (Kavita's key
  is part of its URLs).
- If a server can't be reached (no answer, a timeout, a 5xx error), the
  page's last copy is shown, with **Offline copy DD/MM HH:MM** in the
  footer. Browsing it works; downloads need the server. A refusal from the
  server (401, 404) is shown as the error: the copy is only for an
  unreachable server.
- A request with no answer, or with a 5xx error, is tried once more after
  1.5 s, as is a download that received nothing. Return still stops it.

## Book details and covers

OK on a catalog book now opens its details before downloading:

- The cover: the entry's OPDS thumbnail (or its image when there is no
  thumbnail), fetched from the catalog's own origin, 1 MB at most, PNG or
  JPEG. It is dithered to a 96×128 1-bit picture and kept in
  `.books/opds-covers/` (256 at most), so it shows again without the network.
  Covers stay black on white in the dark themes.
- The title (two lines), the author, and the description. An HTML
  description is shown as plain text. The wheel scrolls it.
- OK downloads the book. If the book is already on the card, OK says so and
  shows it in the library.

## Folders and large libraries

- **Sort: Folders** (Sort on the home screen now cycles Title A-Z,
  Recently read, Recently added, Folders) shows the library as the card's
  folders. Child folders come first (`[DIR]`), then the folder's books A-Z.
- The header shows where you are, `Books > Fiction > Sci-fi`, cut from the
  left when it is long. OK opens a folder; Back goes up one folder, then
  home. **Browse files** opens the current book's folder with the book
  selected.
- The folders come from the scanned book paths, so Books doesn't walk the
  card twice, and folders with no books are not listed.
- The scan now takes up to 4000 books in 1024 folders (it was 512 books in
  256 folders), up to 5 folders deep. On the host, 4000 books scan, sort
  and show folder by folder in about 0.1 s. On the Q2, the SD card sets the
  pace and hasn't been measured yet.
- Searching still covers the whole library, whatever the sort.

## Sync conflicts

Sync: upload and Sync: download (KOReader sync, Kavita 0.8.7+) now ask
instead of refusing or jumping back without a word:

- **Upload** when the server is further on (another device read ahead):
  a dialog shows both percentages and the other device's name. You choose
  **Go to the server's N%**, **Upload this Q2's N%** or **Cancel**.
- **Download** when the server is behind this page (an older position):
  **Go to the server's N%**, **Keep and upload N%**, or **Cancel**. A
  server further on is applied without a question, as before.
- Two positions within 0.2 % of the book, or at the same XPath, are the
  same place: no conflict.

## Not in M4

- **Syncing highlights.** The KOReader sync protocol only stores a reading
  position. Kavita 0.8.8 and later have highlights in their own REST API,
  which needs its own sign-in, its chapter ids and its own highlight
  format. Books doesn't use it yet. Highlights stay on the card; Export
  notes writes them to `Clippings/`.
- Reading the network cover into the library after a download: the
  library's own cover is still taken from the EPUB when you first open it.

## Tests

- `books_opds_kavita_and_koreader_transport_contract` (C++):
  `connected.conf` with several servers, `[server]` blocks past 8 dropped,
  Basic credentials only to the same origin, saving (mode 0600, sync
  settings kept, a bad server refused without touching the file).
- `books_opds_servers_offline_and_retry`: a saved server's credentials, a
  503 tried once more after a pause, a 404 not retried, the offline copy
  marked offline, a copy for another URL ignored, the cache kept to 64
  pages.
- `books_opds_details_and_covers`: an HTML description made plain text,
  the thumbnail chosen over the full image, the cover dithered, and kept on
  the card for the next time.
- `books_shelf_library_history` (C++): folder views, breadcrumbs, and the
  4000-book scan.
- The T9 keypad test: URL mode.
- `books_koreader_sync_conflicts`: server ahead on upload, server behind on
  download, forced either way, a small gap not a conflict.
