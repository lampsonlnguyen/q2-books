# M5: EPUB fidelity and resilience (v0.13)

Status: **released in 1.2.0**. The corpus
runs on the host (GCC, Clang, and the ASan build for the new code). Nothing
here has been measured on a physical Q2.

## What the corpus covers

`crosspoint-core/tests/make_m5_corpus.py` writes twelve small EPUBs. Each
has unique `M5-…` marker text, so the checks see what reached the reader's
text output, not just that the file opened. `tests/m5_corpus_test.py` runs the
real `books-reader` (`--validate`, `--walk`, `--inspect-styles`) over them.

| Book | Exercises | Result |
|---|---|---|
| nested-css | descendant selectors, inherited centring, em via CSS, `display:none`, `!important` | Pass: indent, alignment and italic are applied; hidden text stays out |
| tables | simple, `colspan`/`rowspan`, nested tables | Pass: every cell's text appears (see differences) |
| ruby | `<ruby>` with `<rt>`, Japanese text | Pass: text appears (see differences) |
| rtl | `dir="rtl"` Arabic and Hebrew, LTR numbers inside | Pass: `rtl=1` on every paragraph |
| footnotes | `epub:type` noteref and footnote asides, one cross-chapter | Pass: note text is in the flow |
| anchors | links across chapters, same-chapter ids, a missing fragment | Pass: broken fragment does not crash |
| images | PNG, a missing image file | Pass: text after the images shows |
| embedded-font | `@font-face` to a file that is not a real font | Pass: falls back, text shows |
| empty-chapter | empty and whitespace-only chapters | Pass: text in the last chapter shows |
| broken-missing-spine | spine item missing from the manifest | Pass: the valid chapter shows |
| entities | `&nbsp;`, `&copy;`, a bare `&`, `&undefined;`, numeric references | Pass after the fix below |
| broken-xml | unclosed and mismatched tags | Pass after the element repair below: the text shows (bold carries on; see differences) |

## Defects fixed

### 1. Stray entities blanked the chapter

**Before:** any XHTML that is not well-formed failed the whole chapter. A
bare `&`, a single `&nbsp;` or `&copy;` (common in real books) made expat
stop, the reader fell back, and the book reported "not supported". The
entity book opened with no text at all.

**Fix:** `lib/Epub/XmlEntityRepair.h` rewrites bytes before expat sees them:

- `&amp; &lt; &gt; &quot; &apos;` and numeric references pass through.
- A name in the existing `lookupHtmlEntity` table becomes its UTF-8 text
  (`&nbsp;`, `&copy;`, `&mdash;` …).
- Any other `&name;` and a bare `&` become `&amp;`, so the text is shown
  literally.
- An entity split across two 1024-byte reads is held until its `;` arrives,
  or flushed as text at the end of the chapter.

It runs in both `ChapterHtmlSlimParser::parseStep()` (the device reading path,
which reads through a 1024-byte buffer) and the host XHTML sink in
`books_reader.cpp`. The parser holds an extra 6.3 KB of buffers while a
chapter is laid out.

### 2. Unclosed and mismatched tags blanked the chapter

**Before:** an unclosed `<b>`, a `</p>` that closed its parent before a child,
an HTML `<br>` (void tag) or a stray `</div>` failed expat for the whole
chapter.

**Fix:** `lib/Epub/XmlTagRepair.h` tracks the open elements. It passes start
tags, text, comments, CDATA and processing instructions through unchanged. It
writes the closing tags a mismatched end tag needs, drops an end tag that
matches nothing open, closes a void tag right after its start tag, and closes
everything still open at the end of the chapter. It works in steps with a
fixed output buffer, so a deep close does not need a large buffer.
`lib/Epub/XmlRepairPipeline.h` runs the entity stage and then this stage, and
both the device parser and the host sink use it.

Limits of the element repair:
- At most 64 open elements and 32 characters per element name. Past those,
  the tag is not tracked and the chapter still fails cleanly.
- A '<' that starts no markup, and a DOCTYPE in the middle of a document, are
  not valid XML and are handled as text or passed through as described.

## Checks

- `books_xml_entity_repair` (new): bare `&`, unknown names, numeric
  validation, named entities, chunk boundary at every position of a mixed
  sample, one byte per read, unterminated and over-long names, output size.
- `books_xml_element_repair` (new): well-formed input (every kind of markup)
  comes out byte for byte the same at every read boundary; exact repairs for
  the common breakage; and 1,500 random malformed documents, cut into random
  reads, that expat must accept after repair.
- `books_m5_difficult_epub_corpus` and `books_m5_difficult_epub_checks` (new):
  the twelve-book corpus above, 40 checks.
- Full suite: GCC 90/90, Clang 90/90, and ASan/UBSan 90/90
  (`books_reader_italic_bold_faces` is skipped by design when fonts are
  absent).

## Known differences (allowed for now)

- **Ruby** is shown inline: the base then the annotation (`漢M5-RUBY-KAN字ji`).
  There is no ruby annotation layout.
- **Tables** are a stacked reading flow, one cell per paragraph, not a grid.
- **Images:** an `alt` text is not shown, and a missing image leaves an empty
  block.
- **Truncated chapters** now load with their text before the cut, instead of
  failing. A ZIP-level truncation is still caught by the archive check.
- **Footnotes** appear inline in the text. The reader's footnote popup is a
  separate feature.
- **Unclosed inline formatting** carries on to later text. An unclosed `<b>`
  makes the paragraphs after it bold until the next close. Browsers stop
  inline formatting at the end of a block; this stage does not yet.
- **Host fonts:** this host has no script fonts (`0/14 scripts loaded`), so
  CJK and Arabic glyphs are not visually checked here. The text itself is
  verified.

## Still open in M5

1. **Upstream comparison:** the corpus checks text, styles and page counts,
   not pixels. A pixel comparison against upstream CrossPoint, rendered with
   the same settings, is not built yet.
2. **Real difficult books:** the corpus is generated. Add real public-domain
   books with tables, ruby and CJK to it before the release.
3. **Q2 hardware:** nothing here was run on a Q2. The parse path change needs
   a page-turn and memory check on the device.
