# Books v0.7.0 — Connected Library (beta)

> Since M4 (after 1.1.1), Online lists several catalog servers, which can be
> added and edited on the Q2; see [the M4 guide](v0.12-library-and-servers.md).

Books 0.7 adds optional **OPDS catalog discovery**, EPUB transfers, and
KOReader-compatible reading-position synchronization for Kavita and compatible
KOSync servers. The Q2 remains a standalone MIPS/Linux SD-card app: neither
ESP32/FreeRTOS firmware nor Q2 Pod's EPUB renderer is used.

## Configure on Shanling Q2

1. Connect the Q2 to your trusted private Wi-Fi in Q2 Pod.
2. Install the Books SD-card ZIP, preserving existing
   `/mnt/mmc/.books` progress, highlights, and book files.
3. Copy `/mnt/mmc/.books/connected.conf.example` to
   `/mnt/mmc/.books/connected.conf`.
4. Edit `opds_url` with the OPDS URL for your personal Kavita account.
   Kavita's OPDS credentials and user-specific URL can be found in the
   account's third-party client settings.
5. Optionally set `sync_url` to the Kavita KOReader endpoint
   `http://YOUR_PRIVATE_LAN_IP:5150/api/koreader/YOUR_AUTH_KEY`.
   Set `sync_username` to your Kavita username and `sync_password`
   to the same third-party auth key used by Kavita's KOReader support.
   Change `enable_sync=0` to `enable_sync=1` to permit manual sync.
6. Restart Books after editing the configuration.

Example (placeholders, **not** actual credentials):

```ini
opds_url=http://192.168.5.100:5150/api/opds/REPLACE_AUTH_KEY
sync_url=http://192.168.5.100:5150/api/koreader/REPLACE_AUTH_KEY
sync_username=YOUR_USERNAME
sync_password=YOUR_AUTH_KEY
enable_sync=1
```

**Security limitation:** the current native POSIX transport supports only
unencrypted `http://`, not HTTPS/TLS. The implementation rejects HTTPS
instead of downgrading. Only use it with a server you control on an isolated,
trusted home network. Do not forward Kavita's port to the public Internet,
use a public Wi-Fi hotspot, or send your auth key across an untrusted LAN.
Credentials are stored in plaintext in the local SD configuration; keep it
private. A future release should add certificate-verified TLS. The ZIP ships
only a blank example, not your personal secrets.

## OPDS browsing and download

- On the Books home screen select **Online** (beside Sort), using the
  wheel and center or touchscreen.
- Browse OPDS folder/catalog rows and EPUB acquisitions. Back returns to
  the prior feed or the home screen.
- Selecting an EPUB downloads the actual ZIP to
  `/mnt/mmc/Books/Online/<Title>-<hash>.epub` and returns to the regular
  bookshelf. The existing CrossPoint EPUB reader opens the downloaded file.
- Network access occurs only after user input. Failure leaves the local book
  collection available without Wi-Fi.
- XML feeds are capped at 512 KiB, individual feeds at 96 entries and
  downloaded EPUBs at 32 MiB. Downloads use a `.part` file, are capped,
  and atomically moved into the library when complete. No download replaces
  an existing EPUB.
- Only same-origin HTTP OPDS links can be followed. Off-site links, HTTPS
  redirects, directory traversal, malformed URLs and unsafe headers fail
  closed rather than leaking an account's catalog token to another host.
- Current catalog support is **OPDS 1.x Atom**, not OPDS 2 JSON.
  Network-dependent cover thumbnails and paginated-feed continuation are
  not yet exposed.

## Reading position synchronization

- Open the same EPUB copy on both devices. Books calculates the same
  **partial-file MD5** hash as the original CrossPoint/KOReader algorithm.
  Different byte versions of an EPUB can have different hashes.
- Center button → Reading settings → **Sync: upload** publishes the exact
  EPUB body-text XPath calculated by the original CrossPoint
  `ChapterXPathResolver`/`ProgressMapper`.
- **Sync: download** fetches a remote XPath and applies it using
  CrossPoint's original spine/visible-text-offset page lookup.
- A percentage alone is not treated as an exact text location. If a remote
  record is substantially further along, the upload is blocked to avoid
  silently overwriting another device's progress. Users explicitly select
  download if they want that position.
- No background polling; all sync is manual and opt-in. Bookmarks and
  highlights do not sync in this version.
- For Kavita, use the KOReader-compatible endpoint. An OPDS URL alone
  cannot synchronize progress; they are separate server interfaces.

## Tests and compatibility

The host (GCC and Clang) and Q2 MIPS/QEMU workflows contain a disposable
localhost fixture that serves a chunked OPDS Atom feed, multiple catalog
levels, an EPUB ZIP download and a KOReader-compatible REST service. It
verifies real OPDS navigation, download integrity, KOReader file hash,
credential headers, and a real CrossPoint XPath upload/download roundtrip.

Existing stability gates remain, including the 129-page forward/backward
render stress test, EPUB font shaping, multilingual 30-language test book,
text selection/highlights, and footnotes.

**Hardware validation required** before claiming full interoperability with
an actual Kavita installation, particularly Wi-Fi behavior, sync endpoints,
touchscreen selection, and responsiveness while downloading. This is a beta
milestone, not a universal online reading service.
