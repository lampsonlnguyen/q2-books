# Books v0.8.0 — Q2 device integration verification

Books remains a standalone Linux/MIPS ebook application hosted by Q2 Pod.
This milestone does not add ESP32 firmware, change device power controls, or
replace the original CrossPoint EPUB layout engine.

## Implemented in the v0.8 development branch

- Q2 Pod wheel sensitivity is read from `/mnt/data/config.ini` in the
  `[Q2POD]` / `WHEELSENSITIVITY` key at launch. Valid canonical values
  are 10–200 in increments of 10; missing/invalid values default to 50%.
  The same 28-units-at-50% scaling is used as Q2 Pod.
- Physical wheel, center/back keys and touchscreen coordinates continue to
  flow through the Books input adapter, independently of the Q2 Pod app UI.
- The 20 ms idle sleep loop was replaced by bounded poll-based socket waits,
  with deadlines for nearby page prefetch, shelf metadata indexing and
  periodic reading-position persistence.
- Signal-aware exit handles SIGINT and SIGTERM. The reader destructor attempts
  a final atomic position save before the input endpoint is released.
- Session profiling is opt-in: create `.books/profile-session` on the SD card
  to log wall time, CPU microseconds, peak RSS, filesystem block I/O, and
  context switches to `.books/startup.log`.
- The Unix input endpoint refuses to replace another active reader socket or
  an unrelated pathname. A stale socket from a crashed reader can be reclaimed.
- Host regression tests cover wheel thresholds and extremes, socket wait and
  ownership, and reading-position persistence. Q2 MIPS/QEMU CI includes an
  idle SIGTERM/cleanup smoke test.

## Release requirements and evidence

These checks MUST pass before a non-beta 0.8.0 release is called verified:

1. Host GCC and Clang CMake tests, including Q2 wheel, input and state tests.
2. Q2 MIPS build and ELF/ABI checks against the pinned Q2 firmware sysroot.
3. QEMU EPUB opening, page traversal, rendering and SIGTERM/socket cleanup.
4. Real Shanling Q2: launch from Library, navigate wheel at 10, 50, 100
   and 200% sensitivity, navigate by touch and Back, change preferences,
   exit the reader and reopen the same book at the exact saved page.
5. Real Q2: turn the display off and on using host Q2 Pod controls, and
   suspend/resume if supported; verify readable display and input afterwards.
   Books must never independently suspend or shut down the device.
6. Real Q2: handle USB connection, temporary SD unavailability, and read-only
   storage without corrupting EPUB files or saved reading state.
7. Real Q2: run a 30-minute reading session with opt-in profiling, record
   RSS and CPU usage while idle and page turning, and verify acceptable
   battery and temperature behavior.
8. Real Q2: verify Q2 Pod restores its own UI and controls after Books
   exits, including after SIGTERM.

Host and QEMU evidence cannot establish hardware screen-off, battery drain,
USB and SD transitions, or real touchscreen calibration. Record those results
separately, including Q2 Pod firmware version and anonymized diagnostic logs.

## Not part of v0.8

HTTPS for OPDS and KOReader synchronization is a future milestone after v0.8.
The v0.7 HTTP transport remains trusted-LAN-only; do not advertise internet-safe
Kavita credentials or disable TLS verification as a workaround.
