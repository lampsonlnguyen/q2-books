# CrossPod v0.9 development — HTTPS transport

CrossPod v0.8.0-beta is already published and remains unchanged. This work
is on the `v0.9-https-transport` branch until reviewed and verified.

## Implemented

- HTTPS `opds_url` and `sync_url` support. Reuses Q2 Pod's system
  `libcurl.so.4`. Certificate roots come from `.crosspod/ca-bundle.pem`,
  Mozilla's root list shipped in the card ZIP (checked at build time by
  `tools/check_ca_bundle.py`); `/etc/scrobble-ca.pem` is only the fallback.
  Q2 Pod's file holds the 8 roots its scrobbler needs and lacks, among
  others, Sectigo/ZeroSSL RSA, Amazon and SSL.com (one of the CAs behind
  Cloudflare's edge certificates), so many Kavita hosts would fail with it.
- Certificate chain and hostname verification are **mandatory**. The Q2 build
  cannot inject a test CA bundle via an environment setting. Q2's clock must
  be reasonably accurate; no time-check bypass or TLS verification bypass.
- HTTP from v0.7 still works for trusted LAN deployments. HTTP and HTTPS are
  never silently interchanged; automatic redirects and OPDS acquisition links
  are restricted to the original scheme, host, and port.
- Requests use bounded callback streaming (up to the existing 64 MiB EPUB
  download cap) instead of reading complete ZIPs into RAM.
- Library navigation and manual KOReader-compatible progress uploads/downloads
  continue to use the existing `httpRequest` and OPDS/XPath mapping.
- No ESP32 firmware or changes to Q2 Pod's screen, power, or Wi-Fi ownership.

## Development validation

- Host URL parsing tests include HTTPS default and custom ports, relative
  links, cross-origin rejection, and HTTPS-to-HTTP downgrade rejection.
- Host integration tests create a temporary TLS server and certificate, then
  confirm trusted HTTPS OPDS Atom browsing, EPUB download and KOReader sync.
  Separate checks reject an untrusted certificate, mismatched hostname and
  cross-origin/downgrade redirects.
- Q2 MIPS build links the device's libcurl rather than a host or bundled TLS
  implementation. Cross-build/QEMU checks must pass before merge.
- Real Q2 validation is still required on Q2 Pod firmware 1.8.0, including
  connecting to a real, trusted HTTPS Kavita host, expired/invalid certificate
  errors, and 30-minute memory/power measurements.

## Configuration

Copy `.crosspod/connected.conf.example` to `.crosspod/connected.conf`.
Replace `opds_url` and `sync_url` with the *full* HTTPS Kavita URLs issued
by your server; do not paste actual authentication tokens into logs or issues.
Use a hostname with a valid certificate (not an unverified self-signed IP).
Keep manual sync disabled until user explicitly enables it.

## Transfers and interruption

- A transfer fails when it stalls (under 1 KB/s for 30 s), not when it is
  long: a large EPUB over a slow link completes (30-minute overall cap).
  HTTP had a 20 s total limit and HTTPS 90 s.
- SIGTERM (Q2 Pod's Return-hold) stops a running transfer within about a
  second and removes its `.part`; Q2 Pod SIGKILLs 3 s after its SIGTERM.
- A download's `.part` is locked while it runs. One left by a killed reader
  is taken over by the next attempt and swept when the app starts, instead
  of blocking that book with "Download already in progress".

## Important limitations

- TLS is not end-to-end verified by an on-device physical test yet.
- HTTPS may not work if Q2 Pod's trust bundle is outdated or the device clock
  is wrong; fix the trust store/time rather than disabling verification.
- HTTP remains available for local backward compatibility. It is not secure
  for untrusted Wi-Fi or Internet-facing credentials.
- Cross-origin redirects are deliberately refused even if both sites use
  HTTPS, to protect OPDS URL tokens and KOReader authentication headers.
